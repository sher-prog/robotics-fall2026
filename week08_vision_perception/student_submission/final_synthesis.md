These three missions showed me that a robot seeing something doesn't mean it can act on it reliably. It depends on how good the detection is and how the controller uses it. In mission1 , the color-based detector did badly. It found the mug correctly in only 1 of 20 images and made 15 wrong boxes. It often picked the shadowed wood on the desk, because the wood and the mug are almost the same color. The learned cup detector made no wrong boxes, but it also found the mug in only 3 of 20 images. It missed the dim, glare, far, occluded and cluttered images. So I don't think either one was reliable. I think the color rule is fragile because it only looks at color. The learned model was more careful, but it missed a lot at the 0.5 threshold. In mission 2 and 3,  the pillar run (20261030T230205-77c6cf2b), the robot centered all four colors one after another and never moved forward. On the track, I changed only the gain. With gain 0.08 (20261030T234121-8bcd0c52) the line stayed far from the center and the average error was 0.49. With gain 1.0 (20261031T000007-3b1649fd) the average error dropped to 0.06 and the robot did not wobble. So the weak gain was why it corrected so slowly. In my practice run (20261030T232935-36221c74), the robot stopped when the strip ended and the camera saw no line. That was the right thing to do.  All of this was in a simulation with clean colors and no people. A colored region in the center doesn't prove what the object is or how far away it is. A real robot would need more sensors and more testing with glare, other objects of the same color, and people around.
